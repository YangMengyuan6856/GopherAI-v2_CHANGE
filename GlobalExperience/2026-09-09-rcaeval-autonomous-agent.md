# RCAEval 从规则回放升级为自主排查 Agent

## 目标与本次边界

用户需要的不是固定顺序查四个工具再匹配规则，而是模型自主选择查询、根据新取得的证据修正假设，最终给出候选故障与需要核查的内容。实现为独立实验入口，保留原规则，不改变正式聊天、原诊断 Harness、人工评测或在线策略。

- 核心：`internal/rcaagent`；云模型适配：`internal/platform/rcaagent`。
- API 仍为 `POST /api/v1/experiments/rca/diagnose`，新增预注册 `autonomous` 策略。
- 网关对浏览器暴露 `/api/experiments/rca`；Axios 已加 `/api`，不能再重复 `/v1`。
- Dashboard M-10 移到 M-09 后，页面主按钮为“启动自主排查 Agent”，旧规则按钮移入折叠对照区。
- 只读工具：总览、详细指标、日志、调用链、历史案例；工具参数绑定当前窗口，模型不能传主机、路径、案例 ID、Shell 或答案查询。
- 单并发、8轮模型、6次工具额度、180秒；复用 Tool Runtime 的 Schema、权限、重复调用防护和 MySQL 审计。

## 真实模型联调经验

1. 单元测试通过只能证明循环和校验代码可用，不能证明真实模型能遵守契约或正确排查。必须记录实际工具顺序、每轮新证据、Token、输出格式失败和最终评分。
2. 原 qwen-turbo 多轮时出现较多 JSON / 引用与数值比较问题。保留失败报告，独立实验默认改用 qwen-plus；普通聊天/RAG 不变。模型参数只允许服务端 `GOPHERAI_RCA_MODEL` 覆盖。
3. “JSON object 输出模式”仅保证 JSON 形式，不保证业务 Schema、证据归属、预算指令或判断正确，Go 端仍需严格校验。不能为了显示成功而跳过校验或改成规则结果。
4. 合理的探索会检查其他服务作为排除项。探索假设允许已观测到的其他服务，最终候选仍限定支持范围；跨服务对比引用允许存在，但不能代替候选自身指标和另一类证据。
5. 历史结果只暴露有界特征和外层 reference 引用，避免嵌套的历史 metric ID 被模型误认为可引用的当前证据。
6. 校验错误要指出具体 candidate 索引及缺失字段，便于模型在剩余预算中自行修正。不要由后端替模型编造 uncertainty、check 或筛选成“正确答案”。预算耗尽仍保留失败。
7. 模型可能擅自推断 JVM / GC、指标单位或因果关系，提示词约束不能彻底消除。这些输出依旧是未经验证的候选；后续步骤不执行，不能宣称已确定机制或修复有效。
8. 之前12例官方答案已查看过；本次真实模型运行只能称已有案例回放，不称新盲测。旧规则6/6和范围外4/6误接纳不属于新 Agent。
9. 第一轮 v1 完整回放仅4/12完成，8次主要是输出校验/预算失败，已知正确2/6。不能靠不断追加提示词掩盖复杂契约的负担。v2取消重复的结构化 hypotheses 和多候选数组，让每轮只提交证据更新、下一动作，最终只提交一个最优先候选；证据准入没有放宽，旧失败全保留。
10. 模型输入要回填其通过校验的原始 wire JSON，而不是前端使用的扩展 DTO；否则会把展示字段变成模型下一轮模仿的输出格式。历史证据保留原始量级、变化和参考波动，不仅给相似度或排序标签。
11. 输出格式被拒绝后，也要把长度受限的被拒绝尝试及具体字段/类型错误回传给模型，才能支持有目标的自纠错；仅说“格式错了”会让模型重做同样的错误。被拒绝内容不执行，仍消耗现有轮数/上下文预算，不泄露提供商错误或密钥。

## 报告与回归

`cmd/rca-agent-eval` 顺序调用真实模型，先写追加检查点，最后输出全报告；目标文件必须不存在，避免覆盖失败。独立评分在 Agent 停止后进行，不把答案加入模型上下文。执行失败不能作为正确拒答计分。

开发尝试按实际发生顺序保留在 `evals/rcaeval/agent-development-*.json`。新回放为 `agent-replay.json`，旧 `holdout.json` 原样保留。报告关联数据 SHA、Prompt SHA 和执行器源码 SHA；Hash 失配时 API 不展示旧成绩。内嵌的执行器文件用 LF规范化 Hash，跨 Windows / Linux 一致。

已运行全量 Go 测试、Vet、Agent/Controller Race、前端 lint / production build。前端仍有既有浏览器数据陈旧及 bundle体积告警，不为这次实验升级无关依赖。

## 阿里云操作规则

继续沿用 `2026-09-03-aliyun-ssh-container-deploy.md`：本地 Go Linux交叉编译与前端静态构建，上传后由既有脚本原子切换。ECS小内存，不运行 Go build、npm build 或本地模型，不新建/删除依赖容器。

主机 `/root/` 与容器 `/root/GopherAI_Runtime/` 不是同一目录。临时评测二进制先 SCP 到主机，再 `docker cp` 到容器并 `chmod 700`；工作目录设置为容器 `/root/GopherAI-` 以复用原配置。API Key从既有容器环境读取，不在终端打印、写入报告或提交仓库。

评测只调用云模型、读取已有公开快照，绝不对生产进程制造故障。报告从容器 `docker cp` 到主机后再 SCP回本地。临时二进制验证完可按明确路径清理；保留评测报告与线上工具审计。

部署使用干净发布 worktree，保留主工作区用户未提交的项目学习文档。最终验证必须检查公网健康、实际模型诊断 API、MySQL ToolAudit、正常缩放下的卡片顺序与深色页面，而不是仅检查构建。

## 固定回放结果（上线前）

当前实现的 `agent-replay.json` 为完整12例：10完成、2输出/预算失败；已知6例服务Top-1为6/6、服务与类型同时正确4/6；范围外4误接纳、2执行失败，不计作正确拒答。87次模型请求，输入469456 / 输出14551 tokens。保留v1与v2反馈修补前的全回放，不覆盖失败。它验证了有界多轮查询的可运行性，但还不能可靠排除未覆盖故障，也没有证明比原规则更准确。
