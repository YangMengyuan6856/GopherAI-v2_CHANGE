# RCAEval 自主排查 Agent：增量规格

2026-09-09，用户明确新目标：模型自主选择排查步骤，依据新证据反复更新候选故障；不是给规则结果加大模型润色。此规格覆盖旧实验的固定调度约束，旧规则和冻结报告原样保留。

## 范围与架构

- 单 Agent / 多轮结构化决策，复用 Eino 模型接口、现有云端模型配置和 Tool Runtime；不新增中间件、不在 ECS 运行模型或编译。
- 开发实测发现原 `qwen-turbo` 在多轮 Schema、引用与数值比较中失败较多，失败报告保留。若既有配置为百炼 `qwen-turbo`，仅此实验默认改用 `qwen-plus`；允许服务端 `GOPHERAI_RCA_MODEL` 指定，浏览器不能更改模型。其余聊天/RAG配置不变。模型选择不是 Agent 框架有效性的替代证明，需另看实际轨迹与正确性。
- 输入仅案例 ID、预注册策略。Agent 初始仅知服务清单、工具契约和治理预算，不获得当前案例真值、旧规则候选、评分报告、案例分组或编码答案的路径。
- 由模型每轮选择 overview / metrics / logs / traces / history 和目标服务；工具绑定当前窗口，真实读取公开数据摘要。历史库只有原来的6条参考，测试答案不作为参考。
- 模型返回可核对的简短假设更新、已有证据引用和下一步/最终结论；不请求、记录或展示私有内部思维链。
- v2 将模型交互契约精简为 action / update / tool 或 final：每轮简短 update 表达假设变化，最终只提交一个最优先 candidate（证据不足为 null）。前端公共 DTO 仍用 candidates 列表包装，不能将其反向作为模型上下文，避免模型模仿展示格式填充占位候选。
- 工具结果回到下一轮上下文；不是事先执行全套工具。最终回答至少引用目标服务详细指标及另一类实际查询证据，且声明不确定性、未执行核查。
- 引用合法不等于因果正确。若无法区分支持范围外的类型，可以拒答；不保证解决原来4/6误接纳。

## 执行与安全边界

- 同时1个实验；最多8次模型请求、6次工具执行额度、180秒总超时、单模型请求35秒、输出1800 tokens/次、单工具1秒及24KB返回。
- 上下文单轮48KB，累积输入180KB；所有重试也消耗轮数和预算。两次连续无新信息/非法输出停止；相同工具参数的重复执行由已有 ActionGuard 阻止。
- 模型不能指定 case_id / target / host / shell / provider / API key，不能调用评分器或创建其他 Agent；日志是数据而不是指令。
- 权限/Schema/审计仍经真实 Tool Runtime；模型请求失败时保留失败状态，不能用确定性答案冒充 Agent。
- HTTP连接取消时传播 context；公开基准数据经已配置云端模型处理，密钥仍留在原环境配置，不写报告。
- 不执行修复，不改变聊天、原诊断、人工标注或线上策略。

## 验证与完成标准

1. 单元测试用受控模型替身验证不同工具顺序、每轮实际传递新证据、引用归属、重复查询、非法工具/参数、注入内容、超时取消、异常不泄密；这些测试不作为诊断质量成绩。
2. 真实模型运行保留模型名、版本/Prompt Hash、每轮摘要与新证据、工具轨迹、Token用量、停止原因和独立评分。运行失败不计为正确拒答。
3. 先用开发集检查接口和输出契约；旧12例答案此前已查看，只能作回放对照，不声称新盲测、统计显著提升或生产准确率。
4. 不覆写旧规则留出报告；真实模型成绩另存文件，保留全部运行和失败，不挑最好一次。后续扩大泛化结论需要另取未看过的新样本。
   第一轮 v1 的12例回放保留为 `agent-replay-initial-v1.json`（4完成、8执行失败、已知2/6服务与类型正确）。v2属于接口精简后的再次回放，不能作为独立新测试或统计显著性证明。
5. 前端主操作为“启动自主排查 Agent”，规则移入对照折叠区。按轮显示简短假设更新、模型选的工具、返回证据和最终结果；支持下载本次轨迹。首页 M-10 排在 M-09 后面。
6. 本地构建测试、原子发布、真实登录态验收后交付，不把仅编译成功当作 Agent 能力验证。

## 验收关注点

用户不用填写标注或手动配置工具。选择案例点击启动，检查至少两轮真实查询与证据更新；不要求每轮都改答案，也不强制不同案例必须采用不同路径。正确性看最后标准答案，自主性看实际决策与查询轨迹，治理看被拒绝的动作和停止边界，三者分开判断。
